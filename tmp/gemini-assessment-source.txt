3. Exact Gemini / API Spend-Cap & Budgeting Procedure
A standard billing alert is a passive notification and NOT a spending cap. To enforce hard cost protection, we define a two-tier spend control architecture:
Tier 1: GCP Quotas & Hard Spending Caps
Step 1: 1. Navigate to Google Cloud Console → IAM & Admin → Quotas & System Limits.
Step 2: 2. Select 'Generative Language API' (Gemini API).
Step 3: 3. Set hard limit on 'Requests per day' (RPD) and 'Tokens per minute' (TPM). Reducing daily quota to match max budget acts as a hard operational cap—once reached, Google rejects further API calls with HTTP 429.
Step 4: 4. Configure GCP Programmatic Budget Notifications linked to a Pub/Sub topic and Cloud Function that programmatically disables the API key if spend reaches 100% of the allocated monthly limit ($50.00).
Tier 2: Application-Level Rate & Cost Caps
App Cap 1: 1. Enforce OCR_MONTHLY_CAP in Lead71 backend environment configuration (hard limit on monthly classification requests per tenant).
App Cap 2: 2. Circuit Breaker: If Gemini returns 5 consecutive HTTP 429 or timeout errors within 5 minutes, Lead71 automatically disables AI calls for 1 hour and routes all traffic to the manual parser.
4. Data Retention & Privacy Position (Paid Tier)
We remove any absolute claim of a universal 30-day data purge. The precise data handling position based on Google Cloud Paid Tier documentation is as follows:
Model Training: On Google Cloud Paid Tier / Enterprise Gemini API agreements, input data (OCR text sent to Gemini) is NOT used to train or improve Google models.
Data Retention: Data is processed transiently in memory to generate the classification response. Account-specific retention depends on whether Cloud Logging / Cloud Audit Logs are enabled in our GCP project. In our default configuration, upstream request bodies are suppressed and NOT saved to GCP log storage.
Data Transmitted: No card images, user session tokens, or stored database records are ever transmitted to Gemini. Only extracted raw text is sent.
